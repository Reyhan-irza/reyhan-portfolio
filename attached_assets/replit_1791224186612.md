# REPLIT.MD — Reyhan Irza Alvano Portfolio
## Master Blueprint, Design System, Motion System, Interaction Rules, and Implementation Contract

> **Purpose:** This file is the single source of truth for redesigning and refining the existing Reyhan Irza Alvano portfolio.
>
> **Primary objective:** Build a distinctive, premium, modern personal portfolio that feels authored rather than AI-generated, while preserving all existing functionality and making desktop + mobile interaction a first-class experience.
>
> **Important:** This is an implementation blueprint, not a loose design suggestion. Do not replace the existing product identity with a generic portfolio template.

---

# 0. NON-NEGOTIABLE PROJECT RULES

These rules override convenience.

## Preserve Existing Functionality

Do not remove, disable, replace, or silently break working features unless explicitly required by the blueprint.

The redesign must preserve the existing functionality where present, including:

- Loading / intro screen
- Background music / MusicController
- Music state persistence
- Achievement system / AchievementToast
- Visitor tracking
- Supabase integration
- News section
- Comments section
- GitHub section
- Contact functionality
- CV / resume download behavior
- Existing project data
- Existing routing
- Existing authentication / admin-related behavior where applicable

If an existing component already works, prefer **refactoring its visual structure** over rebuilding its business logic from scratch.

## Repository Safety

Before changing anything:

1. Inspect the repository structure.
2. Inspect the current `package.json`.
3. Inspect the current application entry point.
4. Inspect existing pages/components/hooks/lib utilities.
5. Identify which components are business-logic critical.
6. Identify existing environment variables and Supabase usage.
7. Confirm the current build command.

Never perform destructive operations such as:

- `git reset --hard`
- force-push
- deleting the repository history
- replacing the whole project with a new scaffold
- removing unrelated working features

unless the user explicitly authorizes it.

## Preserve Vercel Compatibility

The project must remain compatible with a normal Vite/Vercel deployment.

Do not introduce unnecessary deployment-specific complexity.

Before completion:

```bash
npm run build
```

must succeed.

If the project uses a different documented build command, respect the existing configuration.

## Color Usage Rules

Dark tones are the foundation.

White/silver are the structural colors.

Blue and violet are accents.

Do NOT overuse accent colors.

Avoid:

- full-screen gradients
- purple/pink/blue rainbow gradients
- neon UI everywhere
- gradient text on every heading
- glowing borders around every card
- excessive ambient blur

Preferred signature gradient:

```text
Silver → Cool Blue → Violet
```

Use this only in carefully selected areas:

- logo lighting
- active progress
- loading indicator
- motion graphics
- selected headings
- subtle image overlays
- rare interactive states

The UI should still look premium when the accent colors are removed.

# 5. TYPOGRAPHY SYSTEM

## Primary Font

**Manrope**

Use Manrope consistently across the site.

Character target:

- modern
- clean
- geometric
- premium
- readable
- slightly distinctive without being gimmicky

Avoid futuristic display fonts.

## Weight System

```text

500 — UI / secondary headings
600 — headings
700 — strong headings
800 — hero / display emphasis
```

Avoid unnecessary 900 weight.

## Type Scale

Use fluid sizing with `clamp()` rather than rigid desktop-only sizes.

Suggested direction:

```text
Display: 72–120px desktop
H1:      56–80px
H2:      40–56px
H3:      24–32px
Body:    16–18px
Meta:    13–14px
Micro:   11–12px
```

These are directional values. Tune per breakpoint.

## Typography Rules

Use:

- large editorial display typography
- strong hierarchy
- generous line-height where needed
- controlled letter-spacing
- uppercase micro-labels sparingly
- readable body copy
- intentional wrapping

Do not:

- use giant headings in every section
- use all caps for all content
- use excessive tracking
- animate every letter separately unless specifically justified

## Desktop

Use a 12-column grid.

Recommended structure:

```text

```

Use a consistent max-width appropriate to the viewport.

## Tablet

Adapt to a reduced grid and maintain rhythm.

## Mobile

Use a clean single-column flow, with selective asymmetry where it improves hierarchy.

## Global Layout Rules

- consistent section padding
- consistent side padding
- deliberate whitespace
- strong alignment
- controlled asymmetry
- visual breathing room
- avoid excessive card nesting

Do not make every section a centered max-width rectangle with identical spacing.

Sections should have different compositions while sharing the same underlying grid.

# 23. MOTION SYSTEM

Motion is a core part of the design.

It must NOT be treated as decoration.

## Motion Personality

- slow
- smooth
- precise
- low-amplitude
- responsive
- layered
- reversible
- intentional

Avoid:

- bounce
- jelly
- excessive elastic
- random spinning
- aggressive zoom
- constant shaking
- “jedag-jedug”
- animation on every element at once

---

# 24. GSAP ARCHITECTURE

Use:

- GSAP
- ScrollTrigger
- timelines
- scrub where appropriate
- `gsap.context()` in React components
- `matchMedia()` or equivalent for responsive behavior
- cleanup on unmount
- pointer helpers such as `quickTo()` where useful

## Core Principle

Use animation progress that follows the user's interaction when the effect is scroll-driven.

Concept:

```text
scroll position
     ↓
animation progress
     ↓
visual state
```

If the user stops halfway, the animation should be able to stop halfway.

Do not build everything as fire-and-forget `gsap.to()` calls.

---

# 25. SCROLL DOWN + SCROLL UP

Both directions are mandatory.

## Scroll Down

Elements can:

- enter
- shift
- compress
- reveal
- draw
- parallax
- transition into depth

## Scroll Up

The same visual states should reverse naturally.

Do NOT:

- reset to start abruptly
- re-run unrelated entrance animations
- snap elements
- hide and instantly show

The page should feel continuous.

# 29. MOBILE INTERACTION — HIGH PRIORITY

Mobile must be interactive, not simply “responsive”.

Because mobile has no pointer:

Use:

- scroll
- touch
- tap
- swipe
- gesture where appropriate

Examples:

Desktop project interaction:
- cursor → parallax / hover

Mobile project interaction:
- scroll → depth movement
- tap → active state
- swipe → gallery if useful

Desktop navigation:
- hover + click

Mobile navigation:
- tap + side panel

Never remove all motion simply because the device is mobile.

---

# 30. MOBILE MOTION ADAPTATION

Mobile should use the same design language with lower intensity.

Reduce:

- parallax distance
- blur
- heavy transforms
- background complexity
- pointer-only behaviors

Preserve:

- scroll-linked motion
- section transitions
- hierarchy
- feedback
- brand geometry
- side navigation motion

Do not merely scale desktop down.

---

# 31. PREFERS-REDUCED-MOTION

Respect:

```css
@media (prefers-reduced-motion: reduce)
```

When reduced motion is enabled:

- reduce or remove large transform-based motion
- avoid continuous ambient animations
- preserve readability
- retain essential interaction
- prefer instant/short transitions

Accessibility must not be an afterthought.
